# AmazonHelp AI Support Agent — Hiver Take-Home

An AI support agent for AmazonHelp (Twitter) that classifies incoming customer
messages into intents, drafts a reply grounded in historically similar
resolved cases, and decides whether to auto-handle or escalate to a human —
with a stated reason for that decision.

## Repo structure

```
src/
  data_loader.py     # loads the Kaggle CSV, reconstructs customer<->brand reply pairs
  retrieval.py        # embedding-based nearest-neighbor grounding
  intents.py           # intent taxonomy + LLM classifier
  escalation.py       # explicit rule-based escalation decision
  reply_drafter.py    # LLM reply generation grounded in retrieved precedent
  agent.py             # wires the above into one SupportAgent.handle() call
  llm_client.py        # Groq API wrapper
eval/
  golden_set_schema.py       # schema + template generator for hand-labeling
  golden_set_labeled_demo.csv # DEMO ONLY — labeled from synthetic mock data, not real submission data
  baselines.py                # trivial + simple (non-LLM) baselines
  metrics.py                   # intent/escalation metrics + LLM-as-judge
  run_eval.py                  # main entrypoint — reproduces headline results
data/
  make_mock_data.py    # generates synthetic data for offline pipeline testing
  mock_twitter_support.csv  # DEMO ONLY — NOT the real Kaggle dataset
tests/
  test_agent_wiring.py  # offline unit tests (mocked LLM calls, no API key needed)
report.md                # full report: framing, baselines, failure analysis, decision log
```

## Setup (should take ~5 minutes)

1. **Clone and install dependencies:**
   ```bash
   pip install -r requirements.txt
   ```

2. **Get a free Groq API key** at https://console.groq.com/keys, then:
   ```bash
   cp .env.example .env
   # edit .env and paste your key
   source .env   # or use python-dotenv / export manually
   ```

3. **Download the real dataset** from Kaggle
   (`thoughtvector/customer-support-on-twitter`) and place the CSV at
   `data/twcs.csv` (or wherever you point `--pairs_csv` at). **We evaluate
   on a subsample, not the full ~3M rows** — see decision log for why.

## Reproducing headline results (~5-10 minutes after setup)

Run the offline wiring tests first (no API key needed, confirms your
environment is set up correctly):
```bash
python -m pytest tests/ -v
```

Build your golden set (see `eval/golden_set_schema.py` for the schema and
`report.md` for how we sampled/labeled ours — 150-250 hand-labeled examples).
A demo labeled set (from synthetic data, NOT real submission data) is at
`eval/golden_set_labeled_demo.csv` purely so you can smoke-test the harness
before your real golden set is ready:

```bash
# smoke test with synthetic data, baselines only, no API key needed:
python eval/run_eval.py \
    --golden_set eval/golden_set_labeled_demo.csv \
    --pairs_csv data/mock_twitter_support.csv \
    --out eval/results_demo.json \
    --skip_llm

# real run, once you have the Kaggle CSV and your own golden set:
python eval/run_eval.py \
    --golden_set eval/golden_set_labeled.csv \
    --pairs_csv data/twcs.csv \
    --out eval/results.json
```

This prints a summary table (intent accuracy/macro-F1, escalation
precision/recall/F1 for both baselines and the LLM agent) and writes full
results to the `--out` JSON file.

### Judge-agreement check (run once, before trusting judge scores at scale)

`run_eval.py` runs the LLM judge on a subset (`--judge_subset_n`, default 40)
and writes scores to the results JSON. Separately hand-score the SAME subset
yourself, then compare with:
```python
from eval.metrics import judge_agreement_report
judge_agreement_report(your_human_overall_scores, judge_overall_scores_from_json)
```
See `report.md` for our own agreement numbers and what they imply about
trusting the judge on the full set.

## Testing an example manually

```bash
python src/agent.py "My package never arrived and it's been 6 days!"
```
Prints the full agent output as JSON: intent, confidence, retrieved
precedent, draft reply, and the escalation decision with reason.

## Note on the demo/mock data in this repo

`data/mock_twitter_support.csv` and `eval/golden_set_labeled_demo.csv` are
**synthetic data generated by `data/make_mock_data.py`**, used only to prove
the pipeline runs end-to-end without needing the real Kaggle download or a
live API key during development. **No reported result in `report.md` is
based on this synthetic data** — all headline numbers come from the real
Kaggle dataset and a hand-labeled golden set. This is called out explicitly
in the decision log.
